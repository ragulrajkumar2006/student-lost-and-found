Relational Schema (after ER-to-Relational mapping)

STUDENT
Student_ID PKINT AUTO_INCREMENT
NameVARCHAR(100) NOT NULL
Email UNIQUEVARCHAR(150) NOT NULL
PhoneVARCHAR(15)
Password_HashVARCHAR(255) NOT NULL
RoleENUM('STUDENT','ADMIN') NOT NULL
ITEM_REPORT
Report_ID PKINT AUTO_INCREMENT
Student_ID FK → STUDENTINT NOT NULL
Item_NameVARCHAR(100) NOT NULL
DescriptionTEXT NOT NULL
Report_TypeENUM('LOST','FOUND') NOT NULL
LocationVARCHAR(150) NOT NULL
Date_ReportedDATE NOT NULL
StatusENUM('OPEN','MATCHED','CLOSED') NOT NULL
CLAIM
Claim_ID PKINT AUTO_INCREMENT
Report_ID FK → ITEM_REPORTINT NOT NULL
Claimant_Student_ID FK → STUDENTINT NOT NULL
Claim_DateDATE NOT NULL
Claim_StatusENUM('PENDING','APPROVED','REJECTED') NOT NULL
RemarksVARCHAR(255)
UNIQUE (Report_ID, Claimant_Student_ID)
ITEM_RETURN
Return_ID PKINT AUTO_INCREMENT
Claim_ID FK → CLAIM UNIQUEINT NOT NULL
Returned_DateDATE NOT NULL
RemarksVARCHAR(255)
Mapping summary: each strong entity becomes a table (Step 1). The 1:N relationships REPORTS, MAKES and RECEIVES become a foreign key on the N-side table (Step 4). The 1:1 relationship RESULTS_IN becomes foreign key Claim_ID in ITEM_RETURN (the total-participation side) with a UNIQUE constraint (Step 3). Arrows point from each foreign key to the primary key it references. All foreign keys use ON DELETE CASCADE.
